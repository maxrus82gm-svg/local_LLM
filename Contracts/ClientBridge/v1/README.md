## Files and compatibility

- openapi.yaml: OpenAPI 3.1, JSON syntax (valid YAML 1.2), base path /bridge/v1, five operations. Bearer scope recorded by x-required-permission and enforced server-side.
- stream-events.schema.json: JSON Schema Draft 2020-12, one data packet per event.
- request-states.md: normative state/ordering/admission/cancellation/retention rules.
- fixtures/: synthetic examples, SSE wire samples and executable offline schema/sequence checks. Values are not live evidence.
- A breaking change needs both coordinators' agreement and a protocol major version change. Additions must be explicitly compatible; schemas currently reject undeclared keys, so adding fields to existing wire objects is not silently compatible. WUA pins exact candidate SHA until agreed. No runtime compatibility claim before WUA review and MVP tests.

## Transport and discovery

WUA backend -> existing Client Bridge HTTP + SSE -> existing Manager HTTPS + NDJSON -> engine. Use low-level Client transport stream_chat/cancel_chat, not laboratory GUI endpoint (it appends history/global prompt). Bridge is in the existing Client, not a second Client, and doesn't connect to engines directly. Loopback-only by default, no LAN scan, no auto-start or port exposure; WUA discovers only an explicitly configured or protected same-user local descriptor of already running Client: bridge_id, protocol_version, origin, credential reference (not secret in browser), launch identity. Exact descriptor storage/bootstrap is implementation P1; ACL to intended OS account, no world-readable tokens, validate live authenticated health and expected bridge_id before catalog/chat, refuse redirects and origin substitution, no remote plain HTTP, preserve TLS verification for remote explicitly authorized endpoints. No Manager credentials to WUA. Separate read/chat/control permissions, control not implemented in v1 MVP. Every operation authenticated; status and cancel are chat scope, own requests only. No wildcard CORS, cache no-store, no secrets in URL/events/logs. Stable bridge_id persists with Client configuration; stable principal_id independent of token rotation.

## Catalogue and identity

GET /models provides targets visible to this principal; READY + allowed_operations contains chat are candidates, not reservation. Include unavailable/busy/stopped known targets without advertising chat; unknown fields null/unknown, never guessed. Actual mode/interactions from verified instance. target_id = "tgt_" + lowercase SHA256 of UTF-8 RFC 8785 canonical JSON array [bridge_id, manager_id, slot_id, model_key]; do not concatenate ambiguous strings. model_key stable model identity; model_id exact upstream engine ID; slot_id identifies independent instance location. Reboot same model in same slot retains target_id, changes instance_id; change model_key changes target_id. WUA stores target_id and refreshes instance_id before a new user-authorized turn; stale instance rejects, no silent fallback to other model/slot. catalog_revision is opaque snapshot identifier, changes for material catalog changes; retrieval polling enough, no subscription in MVP. Unrelated revision change alone is not a rejection for matching verified target/instance. If unknown model_key or active identity cannot be verified, don't advertise READY chat. Config fields in catalogue/meta report actual/default launch configuration IDs/revisions/hardware profile if verified; configuration_lab unsupported and nullable fields until research #6 implemented. No launch, stop, hot apply or auto default selection in this MVP. Do not invent engine maximum.

## Stateless request contract

WUA sends ordered complete messages, optional WUA conversation_id/turn_id and request-scoped options, stable unique request_id and exact target_id/instance_id. Never create GUI chat, append Client history, add Global Prompt V4, truncate/compact or synthesize instructions. Manager currently supports user/assistant, final user message, assistant reasoning_content only if supported and explicitly supplied; assistant content may be empty only with nonempty assistant reasoning_content. Other roles in schema are recognized for explicit 422 unsupported_capability, not accepted in MVP. System/developer/tool instructions never silently rewritten into user text. Native system-role/tool calls/live steering/replay/detached/control unsupported. Structured tool orchestration and Working Memory remain WUA responsibilities. No tools parameter yet. If caller asks for unadvertised thinking/effort/output option or assistant reasoning capability, reject explicit unsupported_capability; "auto" requests existing engine behaviour. max_output_tokens absent means no arbitrary Bridge output token ceiling; actual engine and policy limits enforced and reported. Generation options match Manager chat_settings.py; unsupported mode/options return 422. No input or output token count from word/character estimates.

Use effective Manager policy (measure request_bytes on the translated Manager payload, including routing/serialization overhead; apply any separate Bridge transport bound explicitly, never silently clip), including request_bytes, history_messages, message_chars, history_chars, response_chars, stream_bytes, timeout_seconds and engine context/output limits, report known values in catalog/meta. Explicit error instead of silently clipping or injecting smaller arbitrary limits. Manager has real byte/character safety policies and idle timeouts; this contract does not promise infinite output or context. First progress/throughput measured, not inferred. Active reasoning is progress; heartbeat not progress. Existing upstream default idle policy must be distinguished from total generation duration. No promise of changing Manager settings in this phase.

## SSE and metrics

HTTP POST /chat/stream responds application/json on rejection, otherwise text/event-stream; charset=utf-8, Cache-Control: no-store. Each event is framed as "event: TYPE\nid: SEQUENCE\ndata: JSON\n\n"; id is decimal sequence within that request (not replay cursor). event name and data.type must agree. A client must support normal SSE multi-line data and UTF-8, ignore comments, reject malformed/inconsistent sequence/target, and persist partial output on disconnect without claiming completion. No Last-Event-ID replay in MVP. Flush each packet as received, do not concatenate reasoning with answer. meta includes actual confirmed identity; subsequent data carries correlation request_id/sequence. status, usage, telemetry may be omitted if absent; done always includes usage object with null unknowns and error field. User/assistant history belongs to WUA. See request-states.md.

Usage reported/partial/unavailable, all token counters either exact nonnegative int or null; provider prompt basis explicitly includes_cached/excludes_cached/unknown. Manager currently emits prompt_tokens and completion_tokens only if supplied; total may be derived only when both same-accounting counters are known, mark provider_and_derived_total. Do not assume prompt basis, cache or phase split, do not count cached or reasoning twice; reason tokens subset of completion when actually known. Unavailable means all counters null/source unavailable; partial means at least one known and at least one unknown. Reported means provider supplied exact prompt/completion/total counters; optional cache/phase may remain null. Partial includes derived totals or unknown core counters. WUA maps this to its own accounting convention; no provider prices or synthetic cost. Engine/Manager/Bridge TTFT from respective request-start to first nonempty reasoning/delta; WUA measures its own TTFT. engine_decode_tokens_per_second only measured decode window and known token count; upstream prefill-inclusive throughput is not decode speed. bridge_forward_ms is same-process receive-to-SSE write delta, not cross-host wall clock subtraction. Unknown telemetry null or omitted; wall-clock dates not used to subtract across hosts.
