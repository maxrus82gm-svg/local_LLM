# Ultra LLM Client — P0, автономный прототип интерфейса

**Статус:** демонстрационный, не рабочий клиент. `index.html` — рабочая **копия существовавшего UL-MGR-0A HTML-макета** из `Manager_Ultra_LLM/index.html`, с минимально изменённым названием, бейджем `UL-CLIENT-P0` и отдельным ключом языка. Сам оригинал среди 16 файлов Manager оставлен неизменным.

Можно открыть `index.html` в браузере как локальный файл. Работают только переключатели RU/EN. Показания моделей — исторические/синтетические, текущей телеметрии **нет**. Кнопки START/STOP/CHAT, выбор backend/model отключены. Нет `fetch`, WebSocket, локального HTTP-порта, WinRM, доступа через SMB к моделям и сохранения секретов. Параметр языка сохраняется только в localStorage браузера.

Проверка статического каркаса (на домашнем ПК):

```powershell
py -3.12 -B -m unittest discover -s Client_Ultra_LLM -p 'test_*.py' -q
```

**План следующей итерации:** согласовать безопасный read-only контракт клиент ↔ серверный Manager и способ авторизации. Только затем заменять mock-состояния реальной телеметрией. Не подключать существующий WinRM напрямую к браузеру, не включать сетевой listener без отдельного USER GO.


## Live Client P1 — несколько Manager, реальные данные

Реальные клиентские программы `live_client.py` (CLI) и `live_client_gui.py` (Tkinter GUI) работают на Windows с Python 3.12. Они читают **любой набор** заранее настроенных Manager из личного `managers.json`, индивидуальные локальные файлы CA-сертификатов и токенов клиента, затем делают настоящие `GET /v1/snapshot` по HTTPS с проверкой сертификата. Прокси ОС намеренно игнорируется, чтобы приватный токен не отправлялся на внешний HTTP/SOCKS proxy. **Нет ни симулированных серверов, ни вымышленных статусов**: при недоступности Manager показывается ошибка, а не мнимая доступность.

Конфиг вне Git с форматом `{"managers":[{"manager_id":"my-node","display_name":"Домашний сервер","endpoint":"https://server.example:8443","ca_cert":"server-cert.pem","token_file":"client-token.txt"}]}`. `ca_cert` и `token_file` разрешаются относительно каталога личного `managers.json`; в репозиторий **не** добавлять токены, приватные ключи и любые реальные секреты. Для каждого компьютера-клиента менеджер должен выдать **отдельный** токен/доступ. Публичный сертификат не заменяет авторизацию.

Запуск после настройки `python -B live_client.py --config <private_managers.json>` или `python -B live_client_gui.py --config <private_managers.json>`. Чтение будет работать через LAN; выход в интернет предполагается **только позднее** при защищённой публикации, не при текущем запуске. У клиента нет SMB-доступа к серверным моделям и права самому завершать или запускать серверные процессы.

**Текущий статус:** исходники CLI/GUI созданы и успешно скомпилированы, но соединение клиент→Manager ещё **NOT RUN** из-за незавершённого безопасного credential/bootstrap. Упакованного Windows-инсталлятора ещё нет. Статический P0 `index.html` — исторический макет, рабочая линия теперь `live_client_gui.py`.
