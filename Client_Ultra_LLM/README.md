# Ultra LLM Client — WEB P1 (настоящий браузерный интерфейс)

## Текущий запуск на Windows — без командной строки

**Для владельца:** на домашнем компьютере `DESKTOP-SC96D3U` на рабочем столе уже создан обычный ярлык **Ultra LLM Client**. Двойной щелчок открывает **веб-панель** в браузере; локальный Python Web Client слушает только `127.0.0.1` на автоматически выбранном порту, токен находится в `%LOCALAPPDATA%\UltraLLM\Client`. Повторный щелчок открывает уже работающий клиент, а не дублирует процесс. Кнопка **«Завершить Web Client»** останавливает локальную программу, не Manager и не Colibri.

**Если папку перенесли на другой Windows-ПК:** скопировать `Client_Ultra_LLM` целиком (включая `web_assets`, `live_client.py`, `pairing_client.py`, `Prepare-ClientPrivate.ps1`, `web_client.py`, VBS). Двойной щелчок `Install_Ultra_LLM_Client.vbs` создаёт обычный ярлык на текущем рабочем столе; `Start_Ultra_LLM_Client.vbs` запускает без установки ярлыка. Все скрипты используют пути относительно своей папки. При переносе нужно снова установить ярлык, его абсолютный путь обновляется. **В этой первой версии требуется установленный Python 3.12** с `pyw.exe` (обычно `C:\Windows\pyw.exe`); независимый дистрибутив без Python — WEB-02 следующая задача. Текущий ярлык домашнего ПК пока ссылается на `M:\GitHub\local_LLM_GPT_docs\Client_Ultra_LLM` (GPT worktree).

**Первоначальная настройка:** если на новом ПК нет локального `managers.json`, автоматически открывается веб-мастер. Нужно знать **имя/ID Manager**, **ID нового клиента**, IP-адрес или DNS-имя Manager, HTTPS-порт (например, `192.168.0.77:8443`), иметь **публичный TLS-сертификат от доверенного администратора**. Серверные пути Colibri/Models для Client **не нужны**. Программа создаёт защищённый каталог пользователя (Windows ACL), генерирует личный токен **локально**, а в браузере показывает **только SHA-256** для администратора. Он должен отдельно зарегистрировать клиента, разрешить ему слоты и IP в Manager. Сам факт создания профиля ещё не подтверждает онлайн-доступ — это WEB-03 для более удобного pairing.

**Рабочая панель:** список всех настроенных Manager, ONLINE/OFFLINE, доступные через API модели, не подтверждённые каталоги моделей отдельно, реальные состояния слотов и RAM, кнопка «Обновить» и автообновление каждые 25 секунд. START/STOP показаны отключёнными **осознанно**, пока нет серверных атомарных резервов и авторизованных команд; не делать вид, что они работают. Tkinter `live_client_gui.py` — исторический диагностический инструмент, не развивать.

**Безопасность:** клиентская веб-часть доступна только на `127.0.0.1`, без WebSockets, без LAN/WAN-портов, отдельные Origin/Host/CSRF ограничения для изменения профиля, строго проверенный HTTPS на стороне Python. JavaScript НЕ получает bearer token, путь к токену или содержимое приватного `managers.json`; все конфиги/ключи/секреты в `%LOCALAPPDATA%\UltraLLM\Client` вне Git с защищённым ACL. При копировании папки на другой ПК эти секреты **не переносить**, а зарегистрировать новый клиент.

**Реальные проверки 11.11.2026:** 18/18 Client tests PASS, 231/231 Manager tests PASS; Node `client.js --check` PASS. HTTP на `127.0.0.1:18479` вернул HTML200, `/api/status` = действующий `manager-server77` ONLINE, `source=LIVE_HOST`, slot1 ready/Qwen3.6, slot2/3 not_running, без прямого чтения секретов браузером. Фактический запуск с домашнего ярлыка проверен: локальный браузерный endpoint ONLINE, повторный щелчок — ровно один `pythonw.exe`. Исходный 16-файловый `manager_dev` и работающий сервер/Valheim не изменялись.

## Исторический P0 — автономный HTML-макет (не путать с действующим Web Client)



**Статус:** демонстрационный, не рабочий клиент. `index.html` — рабочая **копия существовавшего UL-MGR-0A HTML-макета** из `Manager_Ultra_LLM/index.html`, с минимально изменённым названием, бейджем `UL-CLIENT-P0` и отдельным ключом языка. Сам оригинал среди 16 файлов Manager оставлен неизменным.

Можно открыть `index.html` в браузере как локальный файл. Работают только переключатели RU/EN. Показания моделей — исторические/синтетические, текущей телеметрии **нет**. Кнопки START/STOP/CHAT, выбор backend/model отключены. Нет `fetch`, WebSocket, локального HTTP-порта, WinRM, доступа через SMB к моделям и сохранения секретов. Параметр языка сохраняется только в localStorage браузера.

Проверка статического каркаса (на домашнем ПК):

```powershell
py -3.12 -B -m unittest discover -s Client_Ultra_LLM -p 'test_*.py' -q
```

**План следующей итерации:** согласовать безопасный read-only контракт клиент ↔ серверный Manager и способ авторизации. Только затем заменять mock-состояния реальной телеметрией. Не подключать существующий WinRM напрямую к браузеру, не включать сетевой listener без отдельного USER GO.


## Live Client P1 — несколько Manager, реальные данные

Реальные клиентские программы `live_client.py` (CLI) и `live_client_gui.py` (Tkinter GUI) работают на Windows с Python 3.12. Они читают **любой набор** заранее настроенных Manager из личного `managers.json`, индивидуальные локальные файлы CA-сертификатов и токенов клиента, затем делают настоящие `GET /v1/snapshot` по HTTPS с проверкой сертификата. Прокси ОС намеренно игнорируется, чтобы приватный токен не отправлялся на внешний HTTP/SOCKS proxy. **Нет ни симулированных серверов, ни вымышленных статусов**: при недоступности Manager показывается ошибка, а не мнимая доступность.

Конфиг вне Git с форматом `{"managers":[{"manager_id":"my-node","client_id":"local-client-1","display_name":"Домашний сервер","endpoint":"https://server.example:8443","ca_cert":"server-cert.pem","token_file":"client-token.txt"}]}`. `ca_cert` и `token_file` разрешаются относительно каталога личного `managers.json`; в репозиторий **не** добавлять токены, приватные ключи и любые реальные секреты. Для каждого компьютера-клиента менеджер должен выдать **отдельный** токен/доступ. Публичный сертификат не заменяет авторизацию.

Запуск после настройки `python -B live_client.py --config <private_managers.json>` или `python -B live_client_gui.py --config <private_managers.json>`. Чтение будет работать через LAN; выход в интернет предполагается **только позднее** при защищённой публикации, не при текущем запуске. У клиента нет SMB-доступа к серверным моделям и права самому завершать или запускать серверные процессы.

**Текущий статус:** исходники CLI/GUI созданы и проверены; клиент сверяет в HTTPS-ответе одновременно `manager_id` и `viewer_id` с `client_id` соответствующего профиля. Защищённое сетевое соединение домашний Client→Manager по LAN пока **NOT RUN** из-за незавершённого безопасного credential/bootstrap. На сервере отдельно прошёл настоящий локальный HTTPS-smoke (не LAN). Упакованного Windows-инсталлятора ещё нет. Статический P0 `index.html` — исторический макет, рабочая линия теперь `live_client_gui.py`.


## Подключение нового Client / индивидуальная регистрация

На компьютере клиента сначала выполнить `Prepare-ClientPrivate.ps1` (настройка каталога `%LOCALAPPDATA%\UltraLLM\Client` с ограниченными ACL). Для домашнего DESKTOP-SC96D3U это **уже выполнено**, каталог и его ACL проверены. Туда также доставлен **только публичный** TLS-сертификат сервера `source-server77.pem`, его SHA-256 совпадает с серверным; приватный ключ не копировался.

Следующее **одно локальное действие владельца на домашнем ПК** — создать собственный токен в защищённом каталоге. Программа `pairing_client.py` не печатает токен в консоль, а выводит только его SHA-256 для сервера:

```powershell
$private=Join-Path $env:LOCALAPPDATA 'UltraLLM\Client'
py -3.12 -B 'M:\GitHub\local_LLM\Client_Ultra_LLM\pairing_client.py' `
 --private-dir $private --manager-id manager-server77 `
 --client-id home-rex --display-name 'Ultra LLM Server 77' `
 --endpoint 'https://192.168.0.77:8443' `
 --ca-public-cert (Join-Path $private 'source-server77.pem')
```

Не вставлять в чат/репозиторий содержимое `.token`, `managers.json`, приватные TLS-ключи. SHA-256 — не исходный токен, его можно передать администратору для команды Manager `create/grant`. Новый Manager добавляется отдельным профилем; несколько Manager поддерживаются одновременно. После запуска защищённого LAN listener и разрешения IP проверка: `py -3.12 -B Client_Ultra_LLM/live_client.py --config "$private\managers.json"` и графический `live_client_gui.py`. Сейчас реальные постоянные credentials ещё НЕ созданы, а LAN Client→Manager ещё NOT VERIFIED.
