# 19 — Qwen3.6-35B-A3B · испытание МАЯК-47

**Подробное досье:** [[19.1_Qwen3.6-35B-A3B_кратко|19.1 — Qwen3.6-35B-A3B · кратко]].  
**Дата:** 02.11.2026 · **Тест:** МАЯК-47 v1.0 · **Раунд:** R1, самостоятельная первая попытка.

## Итог для владельца

**Вердикт независимого текстового ревью: R1 = REVISE / NOT COMPILATION-READY.** Модель описала нужную архитектуру и предусмотрела несколько правильных деталей, но её полный ответ содержит ошибки Unreal Header Tool (UHT), ошибки C++ и Unreal API. Особенно опасны повторное создание компонентов камеры/Spring Arm, изменение корня ACharacter и неверная привязка Enhanced Input. Код в представленном виде нельзя считать пригодным для подключения в UE5.

**Собственная проверка модели заявила все 12 требований выполненными.** Это не подтверждается кодом. **UHT / Unreal Build Tool / редактор / поведенческий тест: NOT RUN.** Формальный `score_10: null` (не ноль). Оценка касается только текста R1, а не всех способностей семейства Qwen.

## Согласованное повторное испытание с глубоким рассуждением — 02.11.2026

Владелец сообщил, что **перезапустил МАЯК-47 для Qwen3.6 с включённым глубоким рассуждением и новыми настройками 16384 токена**. Предыдущий R1 **не переписывать**: исходный тест был выполнен до обновления профиля (ctx8192), фактический флаг Thinking из того запроса не зафиксирован. **Ответ нового запуска получен и независимо проверен**: вложение владельца `Вставленный текст(20261102-042242).txt` (308 строк по отображению, около 16 КБ; SHA-256 `8364b3b5500c7964c86b713b956ba2666e02d72c6816c39b97e9e53760289a4c`). **Текстовый результат: REVISE, но заметно лучше старого R1.** Метка `R1-DEEP` условная: владелец сообщил о перезапуске с Reasoning/16K, но точный отправленный текст и effective `enable_thinking` из API не зафиксированы. Если в запросе были адресные замечания R1, переклассифицировать как `R2-ASSISTED`. Реальные UHT/UBT/runtime NOT RUN.

Если повторно отправлен **буквально тот же неизменённый эталон** без замечаний по старому коду, считать новым независимым `R1-DEEP / CLEAN RETEST`; если переданы 12 замечаний к старому ответу — отдельный `R2-ASSISTED`. Новый ответ уже получен; его проверенный результат и сравнение со старым R1 записаны ниже, в отдельном разделе «R1-DEEP». До подтверждения запроса не приписывать улучшение исключительно режиму thinking. Перед новой отправкой в текущем UI вручную включить Reasoning, так как он явно посылает `enable_thinking:false` по умолчанию (серверный `COLI_THINK=1` не переопределяет это).

После получения провести `OLD vs DEEP`: Unreal API/UHT, создание компонентов, Enhanced Input, получение трансформа камеры, cooldown, самоисправления, 12 пунктов, временные/ресурсные показатели и доступность следующего запроса; **отделять контекстный прирост с 8192 до 16384 от влияния Thinking**. Запись только сюда и в №19.1, без новых документов.

## 2. Что модель сделала правильно

- Выделила персонажа, лампу и Unreal-интерфейс; предложила `LineTraceSingleByChannel` с `ECC_Visibility`.
- Указала **ровно 425 см**, событие `ETriggerEvent::Started`, **локальные +35 см по Z** относительно меша.
- Схема cooldown у каждой лампы использует `GetTimeSeconds()` и `LastInteractionTime = -0.35f`: первое взаимодействие потенциально доступно сразу, а последующие ограничены 0,35 с.
- Запрет на использование `Tick()` для взаимодействия фактически соблюдён.
- Самостоятельно заметила, что отсутствует настройка Input Mapping Context, однако не встроила одно завершённое корректное решение.

## 5. Сопоставление и решение

**По скорости:** владелец на том же сервере заметил, что Qwen3.6 генерирует значительно быстрее Qwen3.8-27B (которая, по наблюдению, давала 2–3 токена/с). **Коэффициент ускорения не установлен**, т.к. нет одинаково снятых счётчиков и замеров.

**По качеству UE5:** Qwen3.6 R1 пока **не проходит**; Qwen3.8 R1 также `REVISE`, KAT R1–R4 тоже `REVISE`. Численно ранжировать их как сопоставимые полноценные решения пока нельзя: KAT получала адресные подсказки в следующих раундах, а у остальных один исходный ответ. В Qwen3.6 несколько особенно серьёзных ошибок — дубли CDO-компонентов и нарушение корня `ACharacter`.

**Самостоятельное ревью:** Qwen3.6 отметила проблему Mapping Context, но пропустила остальные блокеры; её заключение «полностью соответствует» неверно. Это важный недостаток для использования в самостоятельном агенте программирования.

**Итог:** `R1 REVISE / TEXT REVIEW COMPLETE / FORMAL SCORE null / UHT, BUILD, RUNTIME NOT RUN`. Эта версия может быть удобной для быстрой генерации заготовок, **но код UE5 требует обязательной ручной проверки**. Не заменять Qwen3-Coder до отдельного сравнительного теста и решения владельца.

## 6. Наблюдение стабильности после длинной генерации — 02.11.2026

**Событие STAB-QWEN36-20261102-001 / источник: владелец:** после выдачи большого ответа МАЯК-47 R1 (572 строки) запущенная через Colibrì Qwen3.6-35B-A3B перестала отвечать на новые сообщения в чате, выглядела «зависшей/уснувшей». Владелец пытался продолжить диалог, ответа не получал. **Реальное восстановление связи пока не подтверждено.** Это инцидент *доступности после длинного ответа*, а не доказанный дефект весов/архитектуры Qwen: возможны процесс движка, supervisor, API, UI, очередь, длительная генерация, нехватка RAM/VRAM или контекст.

**Для сравнения:** по сообщению владельца при предыдущем тестировании KAT-Coder такой потери отклика **не наблюдалось**; это полезное субъективное сравнительное свидетельство, не подтверждённый непрерывный стресс-тест KAT. Qwen3.6 ранее субъективно значительно быстрее Qwen3.8, но единственный длинный прогон показал риск стабильности. Tok/s и ресурсы при сбое НЕ ИЗМЕРЕНЫ.

**Решение владельца:** на текущем этапе **не проводить обязательное расследование или восстановление** — зафиксировать лишь факт отсутствия ответа после большой задачи. После каждого будущего прогона владелец сообщит, продолжила ли модель отвечать. При желании позже сравнить с KAT в одинаковом сценарии, а диагностику Colibrì провести отдельно. Причина пока UNKNOWN; никаких изменений процесса, логов, движка и параметров API ради диагностики не предпринималось.

**R2:** владелец одобрил исправительный раунд и попросил продолжить без обязательной диагностики зависания. **`R2 APPROVED / PROMPT PREPARED / RESPONSE NOT RECEIVED`**; если текущая сессия не отвечает, пользователь может штатно запустить новую сессию и передать R1 + единое исправительное задание. Важное ограничение: ссылка на прежний контекст после новой сессии не гарантируется; требуется предоставить исходный ответ R1. Результат R2 должен обновляться в этом же №19/19.1. Новые файлы не создавать.

**Вывод человеческим языком:** модель действительно стала лучше понимать состав классов и писать связный код. Особенно заметны исправления создания компонентов, ввода и управления светом.
