# 19.1 — Qwen3.6-35B-A3B · кратко

**Дата:** 02.11.2026 · **Модель:** Qwen3.6-35B-A3B UD-Q4_K_M · **Среда:** Colibrì Ultra на сервере с RTX 3070 8 ГБ, RAM ~48 ГБ.

**Новая серия 02.11:** владелец перезапустил тест с глубоким рассуждением и лимитом ctx 16384. Старый R1 сохраняет `REVISE`; **новый ответ получен и проверен: R1-DEEP (предварительная классификация), REVISE, но лучше старого R1**. Для веб-чата переключатель Reasoning требуется включить вручную. При получении сравнить качество UE5/C++, саморевью и факт дальнейшего ответа модели. Изменились и Reasoning, и context window, поэтому нельзя приписывать всю разницу одному параметру.

## Новый результат — R1-DEEP (02.11.2026)

**Статус:** `REVISE / IMPROVED vs R1 / NO UE5 BUILD`. По словам владельца включены глубокое рассуждение и 16K; фактический API флаг `enable_thinking` не подтверждён. Источник нового ответа: `Вставленный текст(20261102-042242).txt` (308 строк отображения). Полное сравнение и матрица 12 пунктов — №19, раздел 7.

**Исправлено:** больше нет двойной камеры и Spring Arm, не меняется Root Character; верная сигнатура `BindAction(UInputAction*)`, правильный `SetupPlayerInputComponent`, применение `AddMappingContext`, `GetPlayerViewPoint`, управление светом через `SetVisibility/SetIntensity`.

**Осталось:** неверно объявлен Unreal `UINTERFACE` (нет парных `UInteractiveObject` и `IInteractiveObject`); в `private` оставлен `UPROPERTY(VisibleAnywhere, BlueprintReadOnly)` без `AllowPrivateAccess`; нет явного `EnhancedInputComponent.h`; подозрителен `FCollisionResponseParams::InitDefault()`; `Triggered` может повторять действия при удержании E, а `GetFirstPlayerController()` берёт не обязательно владельца персонажа. Модель снова объявила все 12 пунктов выполненными, несмотря на блокеры.

**Сравнение:** улучшение C++ структуры заметное, **качество самостоятельного ревью остаётся ненадёжным**. Не приписывать результат только thinking: 8192→16384 одновременно; исходный prompt и реальный API режим неизвестны. Балл `score_10:null`, UHT/UBT/RUNTIME NOT RUN. **Стабильность после нового длинного ответа: RECOVERED AFTER LONG DELAY.** В 09:35 отправлено «Ты тут?»; по уточнению владельца, **отклик восстановился около 09:50 либо раньше**. Задержка **до примерно 15 минут**, точный момент не замечен. Во время ожидания RAM была занята, GPU нагружен; это не доказывает причину. Следующий шаг — отдельно сравнить с KAT и проверить переход на новую чистую логическую сессию без повторной загрузки весов.

## Что хорошо

- На сервере **реально отвечает в интерфейсе**, по наблюдению владельца **существенно быстрее Qwen3.8-27B**. Численных измерений токенов/с ещё нет.
- В коде есть нужные 425 см, смещение света +35 см, задержка 0,35 с с доступным первым нажатием.
- Работа без Tick, общая архитектура персонаж → Trace → интерфейс → лампа понятна.

## Что плохо

- Дважды создаёт `OurCamera` и `SpringArm`, меняет корневой компонент `ACharacter`.
- Ошибки UHT/Unreal-интерфейса, закрытого `UPROPERTY`, недостающего `UpdateLightState`.
- Не компилируемый `BindAction`, неправильный `Super::SetupPlayerComponent`, несуществующая сигнатура получения трансформа камеры.
- Использует сомнительное `LampLight->bEnabled`, оставляет разрозненные и частично ошибочные варианты подключения Mapping Context.
- Саморевью заявило **12/12**, хотя ключевые дефекты не устранены.

## Вывод и следующее действие

**Быстрая модель ≠ готовый UE5-код.** Для помощи человеку и подготовки черновиков интересна; автономно создавать рабочий C++ проект пока не следует. По итогам одного R1 не установлено, что она может заменить Qwen3-Coder по качеству программирования.

**Важное уточнение:** серверный default-on установлен для будущих API-запросов, но интерфейс браузера по умолчанию отправляет `enable_thinking:false`. Для воспроизводимого нового прогона необходимо явно включить Reasoning; без подтверждения нельзя утверждать, что новый ответ действительно получен в режиме deep.

**Инцидент стабильности STAB-QWEN36-20261102-001 (со слов владельца):** после длинного R1 модель перестала отвечать на последующие сообщения в Colibrì. Причина не установлена: движок, API, чат, очередь, память и контекст ещё не проверены. **У KAT-Coder подобного владелец не наблюдал**, но это не гарантирует абсолютную стабильность KAT. Qwen3.6 быстрее по впечатлению, **устойчивость длинных сессий пока под вопросом**.

**Решение владельца:** потерю отклика после R1 фиксируем как наблюдение, **обязательное расследование не проводим**. После каждого будущего испытания владелец отдельно сообщает, ответила ли модель на следующее сообщение. **Исправительный R2-ASSISTED остаётся отдельной возможной стадией; новый deep-прогон получен, но пока не подтверждено, давались ли адресные подсказки**. Для следующего запуска Qwen3.6 установлено `ctx=16384` (в R1 использовалось старое значение профиля 8192); устойчивость на 16K не проверена. Обновлять №19/19.1, новых файлов не создавать.

**Синхронизация:** технические подробности и матрица 12 требований — в №19; общий рейтинг — №15; актуальный статус — №13. В графе единственная связь этой краткой карточки идёт от №19.
