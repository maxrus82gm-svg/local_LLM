# Управление Colibri в Ultra LLM

Скрипты находятся в `\\192.168.0.77\Server\Ultra_LLM\Colibri`.
**Запускать их нужно на самом DESKTOP-KT4G5SM**, из локальной папки
`C:\Server\Ultra_LLM\Colibri`, под тем пользователем Windows, который устанавливал Colibri.
Запуск BAT с домашнего ПК по сетевому пути выполняет его на домашнем ПК; скрипты это запрещают.

## Первый шаг: проверить существующую установку

Дважды щёлкните `ULTRA-STATUS.bat` на сервере. Он ничего не устанавливает и не запускает модель.
Будут показаны состояние API, модель, сохранённое имя модели, процессы Colibri,
RAM, выбранный backend, доступные сведения NVIDIA, путь и последние строки журнала.
Также проверяются заголовки весов выбранной модели: 49 файлов Qwen или 17 файлов DeepSeek.
Без явного `--model` используется профиль последней управляемой сессии (изначально Qwen).

Результат записывается в:

```text
..\Documents\Reports\CODEX-ULTRA-LLM-COLIBRI-START-001\SERVER-STATUS.json
..\Documents\Reports\CODEX-ULTRA-LLM-COLIBRI-START-001\SERVER-STATUS.md
```

При ошибке конфигурации сохраняется `LAST-ERROR.json` в том же каталоге.
Если другой процесс удерживает `SERVER-STATUS.json` открытым без разрешения на замену
(Windows `WinError 5`), статус записывается под уникальным именем `SERVER-STATUS-<timestamp>-<pid>.json`,
а в консоль выводится WARNING с точным путём. Это не блокирует START, STOP или STATUS.
После закрытия программы, удерживающей исходный JSON, обычная запись возобновится.
Открытый в редакторе файл отчёта не следует считать доказательством текущего состояния модели.
Существующий конфиг читается из `%LOCALAPPDATA%\colibri\setup.json`;
учитывается также заданный пользователем `COLI_SETUP_HOME` или явный `--setup-home`.
Если конфиг принадлежит silver, запускайте скрипт как silver, а не как другой администратор.

## Запуск

Дважды щёлкните `ULTRA-START.bat`, чтобы запустить последнюю выбранную модель.
Для выбора между моделями используйте `ULTRA-SELECT.bat` — меню описано ниже.

- Требуется уже установленный `py -3.12`, существующий runtime и `setup.json`.
- Используются сохранённые launcher, runtime, backend, адрес, порт и окружение.
  В том же runtime выбирается движок семейства: `qwen36.exe` или `deepseek_v4.exe`.
- Команда движка — `serve`. Команды `setup`, `start`, `build`, установщики и скачивания не вызываются.
- Каждый профиль закреплён за своей существующей папкой в `Base_LLM\Models` и проверяется по геометрии и структуре весов.
- Для Qwen сохранены **сессионные** `--ram 12 --ctx 16384 --ngen 16384 --cap 32`. Для DeepSeek установлены `--ram 24 --ctx 16384 --ngen 16384 --cap 16`. Автоматический подбор кэша/tiers и сохранённые tune-профили отключены. Запрос и ответ делят контекстное окно; `--ngen` не гарантирует ответ такой длины. Изменение параметров действует только после STOP и нового START на сервере. Временный вариант Qwen с меньшим окном: `ULTRA-START.bat --model qwen --ctx 4096`.
- Причина ограничений: исходный автоматический режим может занять почти всю доступную RAM. `--ram` — бюджет планировщика, а не жёсткий лимит Windows. Отдельный supervisor следит за запасом свободной памяти и при его исчерпании останавливает только собственный Colibri.
- `setup.json` не переписывается. Backend автоматически не меняется; при ошибке GPU выводится ошибка/журнал.
- Дубликат при уже найденном gateway/движке не запускается. Занятый порт автоматически не меняется.
- Успех сообщается после проверки `/health`, API model ID, собственного gateway и живого процесса движка. Тайм-аут загрузки не считается успешным запуском.

Адрес API берётся из существующей конфигурации и печатается в окне, например
`http://127.0.0.1:8000/v1`. Адрес 127.0.0.1 относится к серверу, не к домашнему ПК.
LAN-доступ и брандмауэр эти скрипты не перенастраивают.

## Выбор Qwen / DeepSeek

На сервере откройте `C:\Server\Ultra_LLM\Colibri\ULTRA-SELECT.bat`:

1. `1` — Qwen3-Coder-30B-A3B.
2. `2` — DeepSeek-V4-Flash-REAP-150B, экспериментальный запуск с дисковой подгрузкой.
3. `3` — отмена.

Одновременно управляется одна модель. Сначала проверяются файлы и runtime выбранной
модели; при их отсутствии действующая сессия не останавливается. Затем выполняется
STOP текущей сессии с проверкой завершения и START выбранной. Старая модель не
восстанавливается автоматически, если новая не смогла загрузиться; выберите `1` для возврата.
Ничего не скачивается, не конвертируется, не распаковывается и не переустанавливается.

Список моделей в подключённом чате показывает то, что уже обслуживает API.
Выбор другого имени в чате сам по себе не загружает другую папку. Переключайте модель
через BAT, затем обновите список моделей в чате. Адрес и порт API остаются прежними.

Прямой запуск DeepSeek с двумя настоящими последовательными ответами:

```bat
ULTRA-START.bat --model deepseek --switch --test
```

Либо `ULTRA-SELECT.bat --test` и пункт `2`. Для возврата к Qwen:

```bat
ULTRA-START.bat --model qwen --switch
```

DeepSeek имеет 43 слоя и 132 эксперта на слой; её 17 шардов занимают 84,69 GB
(78,87 GiB). По исходникам этой версии Colibri формат FP4-экспертов / FP8 dense
поддерживается движком напрямую. Структурная проверка индекса и заголовков
не является проверкой каждого байта весов или подтверждением генерации.

На сервере 47,94 GiB RAM и RTX 3070 8 GiB, поэтому все веса не поместятся в память.
Colibri должен читать экспертов с диска и кэшировать часть в RAM. Это может быть
медленно; скорость до реального теста неизвестна. Параметры DeepSeek устанавливают окно контекста 16384 токена и отключают reasoning
и speculative MTP/draft. Увеличенное окно может повысить расход памяти и замедлить генерацию.
`--ram 24` оставляет запас системе и относится только к процессам этой сессии.

Для CUDA нужен уже установленный `deepseek_v4.exe` и `coli_cuda_dsv4.dll` рядом
с launcher. Используется generic CUDA DLL для RTX 30, не DeepGEMM для RTX 50.
Сессионный режим для 8 GiB VRAM: dense и attention на GPU, prefill MoE на CPU,
не более 32 зеркал экспертов, резерв VRAM 768 MiB. CPU можно выбрать явно через
`--backend cpu`; профиль Vulkan для DeepSeek не заявляется рабочим.
Отсутствующая DLL не устанавливается автоматически. Наличие файлов доступных
профилей сохраняется STATUS в `available_profiles`; оно не доказывает работу GPU.
Выбранный `cuda` — настройка, а фактическую работу нужно подтвердить журналом,
NVIDIA process list и результатами генерации.

Первая загрузка может занять больше 10 минут из-за чтения/прогрева кэша. Тайм-аут
не считается успехом; supervisor продолжает наблюдение, доступны STATUS и STOP.

## Два реальных последовательных ответа

В командной строке **на сервере**:

```bat
ULTRA-START.bat --test
```

Либо для уже работающего управляемого API:

```bat
ULTRA-STATUS.bat --test
```

Отправляются два коротких последовательных запроса, второй использует историю первого.
Проверяется неизменность PID и времени создания движка между ответами.
Для каждого ответа фиксируются число токенов, полное время, время до первого текста,
скорость **с учётом обработки промпта**, данные `/profile` и NVIDIA после ответа.
Результат: `REAL-GENERATION-TESTS.json` и отдельный `REAL-GENERATION-TESTS-qwen.json`
либо `REAL-GENERATION-TESTS-deepseek.json` в каталоге отчёта. Пустой/незавершённый ответ,
отсутствие измеренного счётчика токенов или перезапуск движка означают ошибку.
Локальные unit-тесты с имитацией API не заменяют этот тест.

## Остановка

Дважды щёлкните `ULTRA-STOP.bat`.

Сначала посылается штатный stop-запрос gateway, чтобы тот закрыл движок и сохранил своё состояние.
Для управляемого запуска проверяются PID и время создания процессов. После ожидания
допускается принудительное завершение только подтверждённых собственных процессов.
Успех не сообщается, если matching gateway/движок или здоровый API остались.
Команды завершения всех `python.exe` или всех процессов по имени не используются.

После старого запуска через START-HERE могут остаться отдельные engine-процессы без родителя.
Обычный STOP их показывает, но автоматически не завершает. После просмотра STATUS
можно явно выполнить:

```bat
ULTRA-STOP.bat --force-orphans
```

Этот режим касается только сирот с **точным путём движка выбранного профиля** и уже
завершившимся родителем. Для Python он не применяется. При отличающихся правах доступа
нужно использовать тот же уровень запуска Windows, что и у Colibri.

Закрытие окна START или Ctrl+C прерывает ожидание в этом окне; фоновой сессией продолжает
управлять supervisor. Для завершения модели используйте STOP.

## Файлы и коды возврата

- `ULTRA-CONTROL.py` — общий контроллер; держите рядом с четырьмя BAT.
- `%LOCALAPPDATA%\colibri\ultra\` — собственные PID/время создания, stop-запросы и отдельные журналы supervisor.
- Журналы runtime и существующие модели не удаляются.
- `0` — проверенная готовность/остановка; `1` — ошибка; `2` — остановлено/загружается/ещё не готово; `3` — попытка запуска BAT на другом компьютере; `130` — ожидание прервано.
- Для вызова из автоматизированной проверки можно задать `set ULTRA_NOPAUSE=1` в её локальном окружении.
- При необходимости параметры одной сессии задаются явно: `ULTRA-START.bat --ram 10 --ctx 2048 --cap 16 --wait 600`.

Оригинальный `START-HERE.bat` не изменён. Установка зависимостей, моделей, автозапуска
Windows и изменение системных настроек не выполняются.

## Состояние проверки

Контроллер проходит локальные тесты без инференса. Проверка настоящего запуска, GPU,
остаточных процессов и скорости модели требует запуска перечисленных BAT на сервере.
Не считать эту инструкцию подтверждением успешного серверного инференса.
