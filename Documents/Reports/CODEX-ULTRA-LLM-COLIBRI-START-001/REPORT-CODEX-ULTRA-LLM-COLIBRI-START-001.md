## DIFF

### START

- Читает существующий setup.json: launcher, engine, backend, host, port и окружение.
- Явно указывает нашу локальную модель и корректный API model ID; модель проверяется по содержимому конфигурации, не по одному имени папки.
- Вызывает serve напрямую. Нет setup/start/build, загрузок, pip/winget, распаковки архивов или автоматической смены порта/backend.
- Перед запуском объясняет сессионные ограничения `--ram 12 --ctx 4096 --cap 32`, отключение auto-tier и tune-профиля. Причина: автоматическая оценка памяти/кэша может занять значительную часть свободной RAM. Существующий setup.json не переписывается.
- RAM-параметр — бюджет планировщика, не системный жёсткий лимит. Supervisor отдельно отслеживает запас свободной RAM и при его истощении останавливает собственную сессию.
- Не создаёт дубликат найденного Colibri. Готовность подтверждается по health, model ID, идентичности gateway и наличию движка; тайм-аут возвращает код 2.

### STOP

- Использует проверенный штатный stop-файл текущего порта, который gateway обрабатывает с корректным закрытием движка.
- Supervisor проверяет PID вместе со временем создания. При необходимости прекращает только собственные проверенные процессы, не все Python по имени.
- Остановка старого неуправляемого запуска сначала пробует тот же graceful-протокол. Неизвестные сироты автоматически не завершаются: отдельный явный `--force-orphans` разрешает только точный настроенный executable движка с уже завершившимся родителем.
- Проверяет отсутствие matching процессов и здорового API; иначе сообщает ошибку, а не успех.

### STATUS / тестирование

- Показывает фактическую локальную модель, сохранённую подпись setup, настроенный backend и отдельные данные работающей сессии.
- Выводит RAM, scoped процессы, health/tiers/hwinfo, NVIDIA GPU/compute-apps, адрес API и путь/хвост журнала. Одно поле backend из конфигурации не объявляется доказательством использования GPU.
- Экспортирует SERVER-STATUS.json/.md либо LAST-ERROR.json для чтения через сеть.
- Режим `ULTRA-START.bat --test` либо `ULTRA-STATUS.bat --test` отправляет два последовательных настоящих запроса. Фиксирует tokens, полное время, TTFT, скорость с учётом prefill, профиль движка и GPU; проверяет неизменность процессов между ответами. Результат сохраняется как REAL-GENERATION-TESTS.json.

### Причина имени Qwen3.6

В family_registry.py семейство движка называется qwen36 и имеет общее display_name Qwen3.6-35B-A3B. При создании setup-конфигурации без каталожной записи make_config берёт именно это имя семейства. При этом тот же движок поддерживает Qwen3-Coder, а геометрически точная функция display_for возвращает Qwen3-Coder-30B-A3B.

Это подтверждённый механизм исходного кода, способный объяснить подпись. Что именно сохранено в серверном setup.json и какой runtime реально отвечал в прошлом запуске, пока не прочитано; этот частный случай нельзя объявить окончательно доказанным. STATUS выводит обе сущности отдельно, а управляемый запуск закрепляет корректный API ID после проверки геометрии.

## PROBLEMS

1. Серверный `%LOCALAPPDATA%\colibri` относится к профилю пользователя на DESKTOP-KT4G5SM и не находится внутри ресурса Server. Чтение через `\\192.168.0.77\Users\silver\AppData\Local\colibri` вернуло Access denied. Права не менялись.
2. Прямой файловый доступ по UNC работает. На момент проверки SSH/WinRM 22/5985/5986 и API 8000/8001/8080 не ответили по IP; RPC 135 открыт, но read-only CIM завершился тайм-аутом. Это не доказывает отсутствия Colibri, который мог слушать только loopback, и не доказывает отсутствия дочернего движка.
3. Поэтому **состояние настоящих серверных процессов, GPU, загрузка весов в движок, корректная остановка серверной сессии и два настоящих ответа пока не проверены**. Colibri на домашнем ПК не запускался. Данных токенов/с на настоящей модели нет; выдуманных результатов нет.
4. Сессионные лимиты выбраны консервативно для первого контролируемого запуска. Это не доказанная причина исторических 26 ГБ и не измеренная оптимальная настройка конкретного GPU. Окончательная настройка требует SERVER-STATUS и журнала с реального сервера.
5. При отсутствии/другом формате existing runtime контроллер остановится с ошибкой; устанавливать или скачивать замену самостоятельно он не будет.
